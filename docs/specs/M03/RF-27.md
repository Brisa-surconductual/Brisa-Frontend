# RF-27 · Captura de respuestas estructuradas

- **Versión del RF que se implementa:** 1.1 (hoja «M03 - Chat» del Excel, descargado el 2026-11-07)
- **Módulo / feature:** M03 · `chat`
- **Rol(es) que lo usan:** ESTUDIANTE
- **Ruta(s):** `/app/estudiante/chat`
- **Contrato de API:** Taiga #250 (Etapa 2, RF-27, RF-28 y RF-29 en un solo endpoint). Implementación en curso en la rama de backend `feat/chat-respuestas-rf27-rf28-rf29`, aún sin merge.
- **Dependencias:** RF-26 (entrega `nodo.entrada`)

## Contrato de API

`POST /chat/sesiones/{idSesion}/respuestas`, con cookie de sesión y cabecera `X-CSRF-Token`.

```json
{
  "idRespuesta": "uuid generado por el cliente",
  "idNodo": "uuid del nodo presentado",
  "tipoEntrada": "ESCALA",
  "valor": 7,
  "capturadaEn": "2026-11-07T10:15:00-05:00",
  "conectividad": "EN_LINEA"
}
```

`valor` según `tipoEntrada`:

| `tipoEntrada` | `valor` |
|---|---|
| `OPCION_UNICA` (llega como `SELECCION_UNICA` en el GET, A-014) | string (el `valor` de la opción) |
| `MULTISELECCION` (llega como `SELECCION_MULTIPLE` en el GET, A-014) | string[] sin repetidos |
| `ESCALA`, `NUMERICO` | number |
| `FECHA_HORA` | string ISO 8601 |
| `BOOLEANO` | boolean |
| `TEXTO_LIBRE` | string |
| `CONTINUAR` | `null` (nodo informativo: acuse de lectura) |

- `idRespuesta` identifica la respuesta. Reenviar el mismo `idRespuesta` devuelve el resultado original sin registrar otra respuesta.
- `capturadaEn` lleva el desfase horario. `conectividad` solo admite `EN_LINEA` en esta etapa.
- Respuesta 200 y errores de validación: ver RF-28 y RF-29.

Errores propios de la captura (cuerpo `{ "statusCode", "codigo", "mensaje", "campo" }`):

| HTTP | `codigo` | Cuándo |
|---|---|---|
| 400 | `TIPO_ENTRADA_NO_PERMITIDO` | `tipoEntrada` no es el del nodo |
| 403 | — | Falta o no coincide el token CSRF |
| 404 | `SESION_NO_ENCONTRADA` | La sesión no existe o no es de la estudiante |
| 409 | `NODO_TERMINAL` | El nodo es el fin del flujo y no admite respuesta |
| 409 | `NODO_DESACTUALIZADO` | `idNodo` ya no es el nodo actual |
| 409 | `SESION_NO_ACTIVA` | La sesión no está ACTIVA |
| 409 | `CAPTURA_FUERA_DE_GRUPAL` | Captura no admitida en la modalidad (A-025) |

## Comportamiento esperado

1. El componente de respuesta corresponde exactamente a `nodo.entrada.tipo`. No se ofrece otro tipo.
2. Texto libre solo existe donde `entrada.tipo` es `TEXTO_LIBRE`; ningún otro componente permite escribir texto arbitrario.
3. El componente respeta la configuración recibida: `opciones` y sus etiquetas, `min`, `max`, `paso`, `etiquetas` de los extremos y `maxCaracteres`.
4. La respuesta se envía con el `valor` en el tipo de dato de la tabla, sin transformarlo (por ejemplo, un número no viaja como texto).
5. `tipoEntrada` es el del nodo presentado, con el nombre que acepta este endpoint (A-014), e `idNodo` es el del nodo presentado; `idRespuesta` es nuevo en cada respuesta distinta y se conserva al reintentar la misma respuesta.
6. Mientras la respuesta se envía, no se puede enviar otra.
7. En un nodo informativo (`entrada: null` o `entrada.tipo: "CONTINUAR"`, y no terminal) la acción de continuar envía `tipoEntrada: "CONTINUAR"` y `valor: null` (RF-27 v1.1).
8. Ante `NODO_DESACTUALIZADO` se vuelve a pedir el nodo actual (RF-26) y se descarta la respuesta pendiente.
9. La respuesta de la estudiante no se registra en consola ni en ningún otro lugar del cliente.

## Criterios de aceptación

- **CA-27-1.** Dado un nodo con `entrada.tipo` X, cuando se presenta, entonces solo hay un componente de respuesta y es el de X.
- **CA-27-2.** Dado un nodo cuyo tipo no es `TEXTO_LIBRE`, cuando se presenta, entonces no existe ningún campo de texto libre.
- **CA-27-3.** Dada una `ESCALA` con `min` 0, `max` 10 y `paso` 1, cuando se presenta, entonces solo se pueden elegir los enteros de 0 a 10 y se ven las etiquetas de los extremos.
- **CA-27-4.** Dada una respuesta `ESCALA` 7, cuando se envía, entonces el cuerpo lleva `valor: 7` (number), `tipoEntrada`, `idNodo`, `idRespuesta`, `capturadaEn` con desfase y `conectividad: "EN_LINEA"`, con `X-CSRF-Token`.
- **CA-27-5.** Dada una `MULTISELECCION` con dos opciones marcadas, cuando se envía, entonces `valor` es un arreglo con los dos `valor` de opción, sin repetidos.
- **CA-27-6.** Dado un nodo informativo no terminal, cuando la estudiante continúa, entonces se envía `tipoEntrada: "CONTINUAR"` y `valor: null`.
- **CA-27-7.** Dado un envío en curso, cuando la estudiante intenta enviar de nuevo, entonces no sale una segunda petición.
- **CA-27-8.** Dado un fallo de red o un 5xx, cuando la estudiante reintenta, entonces se reenvía el mismo `idRespuesta`.
- **CA-27-9.** Dado un 409 `NODO_DESACTUALIZADO`, cuando llega, entonces se vuelve a pedir el nodo actual.
- **CA-27-10.** En ningún caso se envía `id_usuario` ni se escribe la respuesta en consola.
- **CA-27-11.** Dado un nodo con `entrada.tipo: "SELECCION_UNICA"`, cuando se envía la respuesta, entonces `tipoEntrada` es `"OPCION_UNICA"` (A-014; ídem `SELECCION_MULTIPLE` → `MULTISELECCION`).

## Estados de interfaz

- **Listo para responder:** componente del tipo del nodo.
- **Carga del nodo:** esqueleto de carga.
- **Enviando:** componente bloqueado e indicador de envío.
- **Error por `codigo`:**
  - `TIPO_ENTRADA_NO_PERMITIDO`: mensaje del backend. Indica un desajuste entre RF-26 y RF-27 (A-014).
  - `NODO_DESACTUALIZADO`: recargar el nodo actual.
  - `NODO_TERMINAL`, `SESION_NO_ACTIVA`, `CAPTURA_FUERA_DE_GRUPAL`: mensaje del backend, sin reintento.
  - `SESION_NO_ENCONTRADA`: mensaje del backend y volver a iniciar la sesión.
  - 403: mensaje del backend tal cual (el guard de CSRF envía «La solicitud no contiene un token CSRF válido para la sesión.») y recargar.
  - 401: inicio de sesión.
  - 5xx o red: reintentar con el mismo `idRespuesta`.
- **Sin conexión:** no se envía; aviso y reintentar (A-025).

## Textos normativos

Del Excel; el backend los envía en `mensaje` y se muestran VERBATIM:

- Tipo de entrada no permitido: «El tipo de respuesta no corresponde al formato requerido.»
- Nodo terminal: «Este nodo no requiere respuesta del usuario.»
- Nodo desactualizado: «La conversación avanzó. Recarga el paso actual.»
- Sesión no activa: «La sesión conversacional no se encuentra activa.»

Un reenvío con el mismo `idRespuesta` no es un error: el backend responde 200 con el resultado original.
