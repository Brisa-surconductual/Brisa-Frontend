# RF-30 · Persistencia de interacciones del chat

- **Versión del RF que se implementa:** 1.1 (hoja «M03 - Chat» de `Especificacion Requerimientos.xlsx`, revisada el 2026-11-20)
- **Módulo / feature:** M03 · `chat`
- **Rol(es) que lo usan:** ESTUDIANTE
- **Ruta(s):** `/app/estudiante/chat/sesion/:idSesion`
- **Contrato de API:** `POST /chat/sesiones/{idSesion}/respuestas`, el mismo endpoint de RF-27 a RF-29, con el cuerpo vigente del backend (`brisa-backend/docs/CONTRATO_RF30_INTERACCIONES.md`, PR #59). El formato camelCase anterior (`idRespuesta`, `capturadaEn`, `conectividad`) quedó obsoleto.
- **Dependencias:** RF-26 (nodo presentado e `idRecurso`), RF-27 a RF-29 (mismo envío), RF-32 (`ultima_secuencia` al reanudar)

## Contrato de API

Cookie de sesión y cabecera `X-CSRF-Token` (las pone `apiClient`).

```json
{
  "id_interaccion": "uuid generado por el cliente",
  "id_nodo": "uuid del nodo presentado",
  "secuencia": 4,
  "tipo_entrada": "ESCALA",
  "valor": 7,
  "timestamp_interaccion": "2026-11-20T10:15:00-05:00",
  "estado_conectividad": "EN_LINEA",
  "recursos_no_presentados": null
}
```

Éxito: `201` (nueva) o `200` (reenvío idéntico, `duplicada: true`):

```json
{ "data": { "id_interaccion": "…", "secuencia": 4, "registrada_en": "2026-11-20T15:15:00.123Z",
            "duplicada": false,
            "transicion": { "id_nodo_origen": "…", "id_nodo_destino": "…", "es_terminal": false },
            "estado_sesion": "ACTIVA" } }
```

Errores propios de RF-30 (además de los de RF-27 a RF-29):

| HTTP | `codigo` | Qué hace la interfaz |
|---|---|---|
| 409 | `SECUENCIA_FUERA_DE_ORDEN` | Resincroniza: vuelve a pedir el nodo actual y el historial (RF-32), sin reenviar. |
| 409 | `ID_INTERACCION_REUTILIZADA` | Muestra el mensaje del backend y ofrece volver al inicio. |
| 422 | `INTERACCION_INCOMPLETA` | Muestra el mensaje del backend y ofrece volver al inicio. |

## Comportamiento esperado

1. Cada respuesta confirmada lleva un `id_interaccion` nuevo (UUID v4 del dispositivo) y la `secuencia` siguiente a la última conocida (`ultima_secuencia + 1`; 1 en una sesión sin interacciones).
2. La última secuencia conocida sale del historial (RF-32) al abrir la conversación y, después, de la `secuencia` que devuelve cada envío exitoso.
3. Un reintento (sin respuesta o 5xx) reenvía exactamente el mismo cuerpo: mismo `id_interaccion`, misma `secuencia` y misma hora. El backend devuelve el resultado original sin duplicar.
4. `timestamp_interaccion` es la hora del dispositivo en ISO 8601 con desfase.
5. `estado_conectividad` es siempre `EN_LINEA`: no hay operación sin conexión (ADR-0005).
6. `recursos_no_presentados` lleva los `idRecurso` del nodo que no se pudieron mostrar después del único reintento (RF-33); `null` si no hubo fallos.
7. El frontend nunca envía `id_usuario` ni registra en consola el cuerpo ni la respuesta.

## Criterios de aceptación

- **CA-30-1.** Dado un nodo ESCALA, cuando el estudiante confirma 7, entonces el cuerpo es exactamente el del contrato, con `secuencia = ultima_secuencia + 1` y sin claves de más.
- **CA-30-2.** Dado un envío exitoso con `secuencia: 4`, cuando el estudiante responde el nodo siguiente, entonces se envía `secuencia: 5`.
- **CA-30-3.** Dado un envío que falla sin respuesta o con 5xx, cuando el estudiante pulsa «Reintentar», entonces se reenvía el mismo `id_interaccion` y la misma `secuencia`.
- **CA-30-4.** Dado un 409 `SECUENCIA_FUERA_DE_ORDEN`, entonces la interfaz vuelve a pedir el nodo actual y el historial, y no reenvía la respuesta.
- **CA-30-5.** Dado un nodo con un recurso que no se pudo mostrar, cuando el estudiante responde, entonces su `idRecurso` viaja en `recursos_no_presentados`.

## Estados de interfaz

Los de RF-27 a RF-29 (enviando, avanzando, error en línea, error con reintento). La resincronización por `SECUENCIA_FUERA_DE_ORDEN` usa el mismo aviso que `NODO_DESACTUALIZADO`.

## Textos normativos

Ninguno propio: los mensajes de error son los del backend, tal cual (ADR-0004).

## Fuera de alcance

- La persistencia y su atomicidad (backend).
- La operación sin conexión y la sincronización diferida (RF-34, RF-35), retiradas por ADR-0005.
