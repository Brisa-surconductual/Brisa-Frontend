# RF-26 · Presentación de mensajes del chat

- **Versión del RF que se implementa:** 1.1 (hoja «M03 - Chat» del Excel, descargado el 2026-11-07)
- **Módulo / feature:** M03 · `chat`
- **Rol(es) que lo usan:** ESTUDIANTE
- **Ruta(s):** `/app/estudiante/chat` (continúa la pantalla de entrada de RF-24)
- **Contrato de API:** Taiga #249 (Etapa 2). Implementación en curso en la rama de backend `feat/chat-rf26-nodo-actual`, aún sin merge. Ver abajo.
- **Dependencias:** RF-24 (inicialización de sesión, entrega `idSesion`), RF-25 (árbol conversacional)

## Contrato de API

`GET /chat/sesiones/{idSesion}/nodo-actual` (cookie de sesión; solo lectura, sin CSRF).

Éxito, 200 (camelCase, sin envoltura `{ data }`):

```json
{
  "idSesion": "uuid",
  "estadoSesion": "ACTIVA",
  "nodo": {
    "idNodo": "uuid",
    "tipoNodo": "PREGUNTA",
    "orden": 3,
    "esTerminal": false,
    "bloques": [
      { "orden": 1, "tipo": "TEXTO", "texto": "¿Cuánto deseo de vapear sientes ahora?" },
      { "orden": 2, "tipo": "INSTRUCCION", "texto": "Elige un valor de 0 a 10." },
      {
        "orden": 3, "tipo": "IMAGEN", "url": "https://…firmada…",
        "expiraEn": "2026-11-07T15:30:00Z", "mimeType": "image/png",
        "textoAlternativo": "Escala ilustrada", "duracionSegundos": null
      }
    ],
    "entrada": {
      "tipo": "ESCALA", "obligatorio": true, "min": 0, "max": 10, "paso": 1,
      "opciones": null, "etiquetas": { "min": "Nada", "max": "Muchísimo" },
      "maxCaracteres": null
    }
  }
}
```

- `bloques[].tipo` ∈ `TEXTO`, `INSTRUCCION`, `IMAGEN`, `VIDEO`, `AUDIO`, `DOCUMENTO`, `GIF`. Los de texto traen `texto`; los multimedia traen `url` firmada con `expiraEn`, `mimeType`, `textoAlternativo` y `duracionSegundos`.
- `nodo.entrada` es `null` cuando el nodo no pide respuesta. Si además `esTerminal` es `false`, es un nodo informativo y se avanza con `CONTINUAR` (RF-27 v1.1). Si `esTerminal` es `true`, es el fin del flujo.
- `entrada.tipo` puede llegar como `SELECCION_UNICA` o `SELECCION_MULTIPLE` (nombres de configuración); equivalen a `OPCION_UNICA` y `MULTISELECCION` (A-014).
- La respuesta no expone reglas de transición, reglas internas de validación ni la marca de captura de perfil clínico (RF-26 v1.1).
- `opciones` es `[{ "valor", "etiqueta" }]` en los tipos de selección.

Errores, cuerpo `{ "statusCode", "codigo", "mensaje" }`:

| HTTP | `codigo` | Cuándo |
|---|---|---|
| 401 | — | Sin sesión de usuario |
| 404 | `SESION_NO_ENCONTRADA` | La sesión no existe o es de otro usuario (se trata como inexistente) |
| 404 | `NODO_INEXISTENTE` | El nodo actual no es válido |
| 409 | `SESION_ERROR_CONFIGURACION` | La sesión quedó en error de configuración |
| 500 | `CONTENIDO_NO_DISPONIBLE` | El nodo no tiene contenido presentable |

## Comportamiento esperado

1. Con la sesión lista (RF-24), la pantalla pide el nodo actual y presenta **solo** su contenido.
2. Los bloques se presentan en el orden de `orden`, sin alterar el texto (ni recortes, ni cambios de mayúsculas, ni formato agregado).
3. `TEXTO` e `INSTRUCCION` se distinguen visualmente; la instrucción no se confunde con el mensaje.
4. Los bloques multimedia se muestran con su `textoAlternativo` como descripción accesible. Si un recurso no carga, se avisa con texto y el resto del nodo sigue visible.
5. Si `entrada` no es `null`, debajo de los bloques aparece el componente de respuesta del tipo indicado (RF-27). Si es `null` y el nodo no es terminal, aparece solo la acción de continuar. Si el nodo es terminal, no aparece ninguna acción de respuesta.
6. Presentar un nodo no valida respuestas ni cambia de nodo: eso ocurre solo al responder (RF-27 a RF-29).
7. Durante la visita, los nodos ya recorridos y las respuestas enviadas siguen visibles en la conversación. Al recargar o reanudar se presenta solo el nodo actual: el historial es de RF-31 y RF-32 (A-018).
8. La interfaz no fabrica errores: muestra el `mensaje` del backend tal cual. Solo hay dos textos propios, para cuando no hay respuesta del backend (sin conexión) o la respuesta no trae `mensaje`. Las acciones que se ofrecen (reintentar, volver a iniciar) dependen de `codigo` y del estado HTTP.
9. Si un recurso multimedia no carga, se vuelve a pedir el nodo actual una sola vez para obtener URL nuevas (la consulta es de solo lectura); si vuelve a fallar, se muestra el aviso de texto (A-017).

## Criterios de aceptación

- **CA-26-1.** Dada una sesión ACTIVA, cuando la pantalla carga, entonces se pide `GET /chat/sesiones/{idSesion}/nodo-actual` con el `idSesion` de RF-24 y sin enviar `id_usuario`.
- **CA-26-2.** Dados bloques con `orden` 2, 1 y 3, cuando se presentan, entonces aparecen en el orden 1, 2, 3.
- **CA-26-3.** Dado un bloque `TEXTO`, cuando se presenta, entonces su texto es idéntico carácter por carácter al recibido.
- **CA-26-4.** Dado un bloque `IMAGEN` con `textoAlternativo`, cuando se presenta, entonces la imagen expone ese texto como alternativa accesible.
- **CA-26-5.** Dado un recurso multimedia que no carga, cuando falla, entonces se ve un aviso de texto en su lugar y los demás bloques siguen visibles.
- **CA-26-6.** Dado un nodo con `entrada.tipo` soportado, cuando se presenta, entonces aparece el componente de ese tipo; dado `entrada: null` y `esTerminal: false`, entonces aparece solo la acción de continuar; dado `esTerminal: true`, entonces no aparece ninguna acción.
- **CA-26-7.** Dado un error 404 `NODO_INEXISTENTE` o 500 `CONTENIDO_NO_DISPONIBLE`, cuando llega, entonces se muestra el `mensaje` del backend tal cual y se ofrece reintentar.
- **CA-26-8.** Dado un 401, cuando llega, entonces se redirige al inicio de sesión.
- **CA-26-9.** Cuando la pantalla presenta un nodo, entonces no se envía ninguna petición de respuesta ni de transición.
- **CA-26-10.** Dado un recurso que falla al cargar, cuando falla por primera vez, entonces se vuelve a pedir el nodo actual una sola vez.

## Estados de interfaz

- **Carga:** esqueleto de carga con la forma de un mensaje del chat, anunciado a lectores de pantalla como carga en curso.
- **Éxito:** bloques del nodo y, según `entrada`, componente de respuesta o acción de continuar.
- **Vacío:** no aplica. Un nodo sin bloques presentables llega como `CONTENIDO_NO_DISPONIBLE`.
- **Error por `codigo`:**
  - `SESION_NO_ENCONTRADA`: mensaje del backend y acción para volver a iniciar la sesión (RF-24).
  - `NODO_INEXISTENTE`, `CONTENIDO_NO_DISPONIBLE`: mensaje del backend y reintentar.
  - `SESION_ERROR_CONFIGURACION` (409): mensaje del backend, sin reintento.
  - 401: inicio de sesión.
- **Sin conexión:** aviso de que se necesita conexión y reintentar. La captura sin conexión no es parte de la Etapa 2 (A-025).

## Textos normativos

El backend los envía en `mensaje` y se muestran VERBATIM:

- Nodo inexistente: «No se pudo recuperar el contenido del chat.»
- Sesión inexistente o de otro usuario: «No se pudo recuperar el contenido del chat.»
- Sesión con error de configuración: «El árbol conversacional para este perfil aún no se encuentra disponible. Contacte al equipo de psicología.»
- Contenido no disponible: «El contenido del nodo no está disponible.»
